# CursorWasher — Windows preview

Windows-версия для предварительной проверки. C# / .NET Framework 4.8, WinForms для цикла событий и трея,
Win32 layered windows для прозрачности, GDI+ для рисования. Внешних пакетов нет.

## Запуск и управление

В рабочем проекте дважды щёлкнуть ярлык **CursorWasher** в корне проекта.
Он запускает `Windows/App/CursorWasher.exe`. Это единственная папка с приложением
для обычного запуска; тесты, диагностические сборки и архивы находятся в `Windows/.build`.
При переносе на другой компьютер достаточно скопировать `CursorWasher.exe` и запустить его.
Изображения уже встроены в исполняемый файл. Права администратора не нужны.

- Клик по ведру или воде запускает мытьё. Запуск происходит после отпускания кнопки.
- Начальный двойной клик запускает один цикл, не прерывая его вторым нажатием.
- Перетаскивание за ведро перемещает его; позиция сохраняется рядом с `.exe`.
- Курсор скрывается **только над непрозрачной областью ведра и водой**.
  Прозрачные поля вокруг ведра пропускают клики другим приложениям.
- При выходе мыши за эту область или потере фокуса настоящий курсор возвращается,
  а нарисованная стрелка тонет. Повторный одиночный клик также прерывает мытьё.
- `Esc` немедленно завершает эффект.
- Меню ведра: «Bring to Front», «Send to Back», «Hide Bucket».
- Меню значка в трее: «Hide Bucket» / «Show Bucket», «Bring to Front»,
  «Send to Back», «Quit». Подписи, порядок и состав действий повторяют Mac.
- Закрытие через `Alt+F4` скрывает ведро; завершение приложения — через «Quit».
- Повторный запуск `.exe` показывает уже работающее ведро на переднем плане,
  включая скрытое, как повторное открытие приложения на Mac.
- После полного цикла приложение пытается вернуть фокус предыдущему окну.
  Если вы уже переключились в другое приложение, новый фокус сохраняется.

Анимация использует округлую границу погружения с оттенком воды, вытянутые
капли акварели и мягкие волны. Всплеск при отмене привязан к моменту, когда
стрелка уходит под воду. Статичное изображение ведра кэшируется для текущего DPI.
Движение воды перенесено из `WaterMotion.swift` и `WaterSurface.swift`: три слоя
акварели смещаются и вращаются с разной скоростью, след появляется с первого
касания, волны проходят к контуру ведра и затухают, краска сохраняет инерцию.
Композиция SourceAtop сохраняет исходную прозрачность воды, включая края.
В `.exe` встроен значок ведра нескольких размеров для Проводника Windows.
Для трея используется общий `Resources/status-bar-icon.svg`, как на Mac;
его цвет адаптируется к светлой/тёмной панели Windows.
Увеличенная стрелка использует наибольшую исходную картинку из активного файла
`.cur` или первого шага `.ani`, с сохранением размера и точки указания обычного
курсора. Для текущей системной стрелки это 128×128 вместо 48×48. В `.ani`
учитывается порядок кадров; выбирается подробная картинка первого шага, а не
другой кадр. Собственная анимация схемы внутри эффекта мытья не проигрывается.
Курсор задаётся в настройках Windows; отдельного выбора в CursorWasher нет.
При отсутствии более подробного исходника сохраняется системный вид курсора.

Скрытие локальное: обработчик `WM_SETCURSOR` вызывает `SetCursor(NULL)`.
Приложение не меняет счётчик `ShowCursor`, системную схему курсоров, положение
мыши и не захватывает ввод на время мытья. Захват мыши используется только при
обычном перетаскивании. Окно анимации пропускает ввод и не получает фокус.

Если системная стрелка временно недоступна (например, прозрачная при работе
инструмента управления экраном), ведро показывает обычное состояние и повторяет
загрузку. Мытьё до получения изображения не начинается.

## Сборка

Из корня проекта в PowerShell:

```powershell
.\Windows\scripts\build.ps1 -Test
```

Скрипт использует компилятор установленного .NET Framework. В основной рабочей копии
версия и сборка читаются из `scripts/project.sh`; в экспортированной папке Windows —
из автоматически созданного `project.json`. Все ресурсы экспорта находятся внутри `Windows/Resources`.
Приложение собирается в `Windows/App`, ярлык `CursorWasher.lnk` обновляется в корне
проекта. Промежуточные файлы и тесты находятся в `Windows/.build`.
При сборке самостоятельной папки Windows ярлык создаётся внутри неё.
Сначала компилируется промежуточная сборка и выполняются проверки, если указан
`-Test`. При их ошибке файл приложения в `Windows/App` остаётся прежним.
Mac-скрипты и `Export` не участвуют.
Перед пересборкой закрыть приложение через меню. Текущая метка Windows-сборки —
`windows-preview`, общая версия приложения не повышалась.

Для локального переносимого архива:

```powershell
.\Windows\scripts\build.ps1 -Test -Package
```

`Windows/.build/Packages/CursorWasher.zip` содержит программу,
краткую инструкцию `START.txt` и лицензию `LICENSE.txt`. Журналы, личные настройки и диагностические программы в архив
не входят. Команда не публикует и не отправляет файлы.

В GitHub Actions та же сборка выполняется на GitHub-hosted Windows runner с
`-Test -Package -NoShortcut`. Дополнительная проверка `scripts/verify-package.ps1`
проверяет название продукта в EXE и содержимое ZIP. Артефакты привязаны к коммиту
и запуску workflow; подпись SignPath пока не подключена.

Для диагностической сборки с кнопкой в панели задач:

```powershell
.\Windows\scripts\build.ps1 -Inspect
```

Она сохраняется в `Windows/.build/Inspection` и нужна для инструментов проверки,
которые не перечисляют служебные окна.
Основная сборка остаётся приложением с треем.

## Устройство кода

- `Sources/Animation`: геометрия и движение в системе координат Mac,
  описание кадра, мытьё, отмена, импульсы воды. Загрузка Windows-курсора сюда не входит.
- `Sources/Rendering`: `CursorSprite` загружает изображения системной стрелки;
  `CursorRenderer` рисует её и частицы, включая буфер для прозрачного окна;
  `Artwork` рисует ведро и воду. `SceneGraphics` задаёт общие правила рисования.
- `Sources/Platform`: Win32-вызовы, показ прозрачных окон и локальное скрытие курсора.
  `SpriteWindow` отвечает за пассивное окно, `LayeredWindow` — за окно ведра.
- `Sources/Runtime`: журнал и чтение/запись положения ведра в прежнем формате.
- `BucketWindow` связывает ввод, анимацию, окна и меню; `Program` запускает приложение
  и обрабатывает повторный запуск и ошибки.
- `Diagnostics`: генерация PNG и нативная проверка окон. Эти исходники включаются
  только с `-Diagnostics` или `-Inspect`; в обычном `.exe` их нет.

## Проверки и ограничения

`-Test` проверяет отказ запуска вне ведра/без фокуса, 500 повторных циклов
скрытия и восстановления с подставным драйвером, идемпотентную очистку,
непрерывность фаз, точность возврата к текущему hotspot, отмену во всех фазах,
растеризацию настоящей Windows-стрелки и прозрачность при DPI 100/125/150/200%.
Также проверяются начальный двойной клик, форма контакта с водой, сохранение
площади вытянутых капель, момент всплеска и отсутствие пикселей под маской воды.
Проверки воды перенесены из `Tests/WaterMotionTests.swift`: направление, границы
движения, постепенное распространение краски, фиксированный центр волн и затухание.
Дополнительно проверяются SourceAtop, неизменность каждого альфа-канала текстуры,
контакт без округлённого погружения, чтение CUR/ANI и повреждённые контейнеры.

Диагностическая команда `--smoke` ненадолго создаёт настоящие прозрачные окна
и трей, проверяет, что анимация не активирует свои окна, затем сама выходит.
Тест прогоняет 90 кадров, проверяет прохождение ввода сквозь пассивное окно,
прозрачные поля, число GDI-объектов и возврат скрытого ведра через тот же сигнал,
который использует второй экземпляр приложения. Запуск проверки:

```powershell
.\Windows\scripts\smoke.ps1
```

Скрипт сам собирает `Windows/.build/Diagnostics/CursorWasher.Diagnostics.exe`.
Эта сборка использует те же служебные окна, что и обычная, без кнопки в панели задач.
Перед проверкой нужно завершить обычный экземпляр через «Quit».
Проверка не скрывает курсор и не имитирует пользовательский ввод.
Для PNG кадров и контактного листа:

```powershell
.\Windows\scripts\build.ps1 -Diagnostics
.\Windows\.build\Diagnostics\CursorWasher.Diagnostics.exe --render-preview Windows\.build\Preview
```

Журнал — `CursorWasher.log` рядом с соответствующим `.exe`. Обычная сборка
не содержит генератора превью и нативного теста.

Проверено 4 октября 2026 после рефакторинга: сборка без предупреждений,
38 590 автоматических проверок; все 29 контрольных PNG до и после изменений
совпали байт в байт. Пройдена проверка настоящих окон с треем при DPI 150%. Прозрачные поля
пропускают ввод, пассивное окно не активируется и не перехватывает ввод у ведра,
сигнал повторного запуска возвращает скрытое ведро. Число GDI-объектов до и после
90 кадров: 28 → 28. Окно анимации создаётся как собственный Win32 HWND.
Полная проверка доставки кликов и видимости указателя на рабочем столе пока не завершена:
инструмент управления экраном видит диагностическое окно, но не получает
изображение (`FrameArrived timed out`) и геометрию для кликов
(`coordinate input geometry is unavailable`).

Перед выпуском проверить вручную: полный цикл с неподвижной мышью, уход за край,
Esc, Alt+Tab, повторный и двойной клик, меню трея во время мытья, перетаскивание,
скрытие/возврат, сон/блокировку, несколько мониторов с разным DPI и принудительное
завершение процесса. Обработчики выхода не выполняются при аварийном завершении;
глобальное состояние курсоров здесь не изменяется, но аварийные сценарии ещё не проверены.

Фазы и тайминги перенесены из Swift (цикл 4,46 с); рисунки ведра и воды общие.
Отрисовка GDI+ близка к Mac-версии, но не является попиксельной копией CoreGraphics.
Причины исправленных и оставшихся различий перечислены в `COMPARISON.md`.
Перемещение между мониторами, удалённый рабочий стол и нестандартные схемы указателей
требуют отдельной проверки. Установщик и публикация в этот этап не входят.
